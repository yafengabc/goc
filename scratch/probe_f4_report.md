# F4 slotCache 值快照语义 — 收益探针报告（只读统计）

探针脚本：`D:\projects\goc\scratch\probe_f4.py`（`python scratch\probe_f4.py` 复现；语料在 `scratch\f4corpus\`，由当前 HEAD goc.exe 现编）。
解析与门控忠实于 `src/opt.go` 的 `slotCache`（clearAll / clearSlot / killReg 全套规则）。

## 0. 口径
- 在**同一份**已优化 .asm（T1.4 当前语义已跑过）上线性重放两套状态：
  - **当前语义**：槽→{reg|imm}，写 r 删除所有源为 r 的槽项。
  - **值快照语义**：槽→拷贝链根（`rootOf` 表），写 r 只删「根=r」的槽项，根为其他寄存器的槽保留；`mov r2,[s]` 根存活即转发。
- 计数对象 = 未尺寸化 `mov <r64>, [rbp-N] / [rip+g]`。
- **增量 delta = 快照转发数 − 当前转发数** = F4 相对 T1.4 的边际可省 mov 数。
- 形态：B=拷贝链根（store 源≠转发根）；A=直接根（store 源==转发根）。
- 编译：`bin\goc.exe -O1/-O2`。**实测此编译器 -O1 与 -O2 产物逐行相同**（bench2/args7 均 0 差异），故下表按单优化级统计，O1/O2 数字一致。examples 实编 78/79 成功，仅 `c23_embed` 失败（嵌入资源类，跳过并记录）。

## 2. 形态 A/B 分类
- **A = 0，B = 5540（100%）**。
- 本体收益全部是拷贝链：`mov rax, rbx; mov [s], rax; ...; mov rax, 2; mov r2, [s]`——当前语义因 store 源 rax 被改写而删槽、走真 load；快照沿 `rax←rbx` 根存活，转发 `r2 = rbx`。已抽 3 处人工复核，语义正确（值确在 rbx 中存活）。
- **形态 A（`mov [s], r` → 写 r → 重载）在正确的快照模型下并不产生收益**：槽根就是 r，r 被写时快照同样删槽。即「直接存值后覆盖该寄存器再重载」无法靠值快照救回——能救的只有「存的是某个仍存活根的拷贝」。这修正了任务书对 A 的预期。

## 3. 结论
1. **静态指令口径可省 ≈ 5540 条 mov / 479428 条指令 ≈ 1.16%**（占冗余槽加载 61425 的 9.0%）。
2. **100% 来自拷贝链根转发**；形态 A 实测为 0。
3. **量级对比**：F4 ≈1.16% < T2.1 ≈3.7% < T1.6 ≈4.6%。是三项里最小的一块。
4. **立项建议：可做，但低优先。** 它是对已有 slotCache 的局部增强（在现有 cache 上维护 `rootOf` 拷贝链），实现成本低、语义安全（只多救当前过度保守删掉的槽，不扩 window），预期 ~1.2% 代码行；建议排在 T1.6 / T2.1 之后作为 T1.4 的收尾优化。注意 O1/O2 当前未分化，收益是静态代码行口径；动态热点放大效应需另行 benchmark。
