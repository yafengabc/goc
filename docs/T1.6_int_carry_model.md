### 1.2 毛利模型

有回绕对的 int 运算 = 运算(1) + shl(1) + sar(1) = 3 条；32 位形式 = 1 条。
毛利 = wrapS × 2（= 指令行净减的上限，未扣窄化点新插 movsxd）。

- 全语料：gross = 35,708 条 = **4.6%**（各文件 3.3%~5.5%）
- bench2.asm（9971 条）：wrapS=250，gross = 500 = **5.0%**
- optprobe.asm（9784 条）：wrapS=238，gross = 476 = **4.9%**

### 1.3 wrap 对前驱分类（bench2 的 250 对）

- ALU 运算结果规范化（add/sub/imul/and/or/xor 之后）：139 对 → 运算直接改 32 位形式
- 内存 dword 装载再符号扩展（`mov eax,[r10]; shl; sar`，genLoadElem）：11 对 → 装载后不再扩展
- 寄存器缓存变量 inc/dec / 槽装载 / CastExpr 规范化：86 对 → inc r12d 等 32 位形式 + (int) 截断改为低 32 位语义
- 跨分支/调用边界的缓存装载+规范化：14 对 → 同上

**结论：250 对全部是纯开销，无一不可消除。**

### 1.4 净收益估算（bench2）

gross −500；窄化点净新增指令主要为 1:1 替换（索引装载 movsxd、ABI 传递不变、除法用 cdq/idiv r11d 反而省 2）：
**净指令减 ≈ 480~500 条 ≈ 4.8~5.0%**。另有编码长度收益（32 位 op 短 1 字节、去掉 shl/sar 500 字节）
与依赖链收益（shl/sar 串行化消除）。最终以实测为准（5 次中位数）。

## 2. 正确模型与不变量

### 2.1 方向辨析结论

- “int 用 64 位算术不回绕”**不可行**：C 语义要求 32 位回绕，64 位 add/sub/imul 溢出污染高位。
- **采用模型**：int（resW==4）算术改用 **32 位操作数指令**（`add eax, r10d` 形态）。
  x86-64 的 32 位操作数指令原生回绕 + 零扩展（二进制补码下与有符号语义一致）。
  一条 `add eax, r10d` 取代三条 `add rax,r10; shl; sar`。需要 64 位符号值处再插 movsxd。
- goa 汇编器已实测支持全部所需形式：`add eax,r10d / sub r10d,eax / imul eax,r10d / imul r11d,4 /
  cmp r10d,eax / shl eax,cl / sar eax,cl / cdq / idiv r11d / div r11d / inc r12d / xor edx,edx /
  movsxd r11, dword [rbp-8]`（见 `bench/_build/ex_probe/probe_t16_forms.c`，汇编通过）。

### 2.2 不变量（改造后）

**寄存器承载的不变量**：resW==4 的 int 值在寄存器里是“低 32 位有效”的物化值；
32 位 op 结果的高 32 位为零（x86 零扩展）。**高 32 位不作承诺**（32 位 op 产零、
cvttsd2si/movsxd/指针装载产符号扩展或全值），低 32 位恒有效。ptrCapable 变量装载例外见 §4。

**槽（内存）的不变量**：int 变量槽保持 8 字节、保持全宽存储/装载（`mov [rbp-N], rax` /
`mov rax, [rbp-N]`）**不变**——这是 goc 子集“int 变量可存 64 位指针”的根基（goclib2.c 大量依赖）。
纯 int 变量装入槽的是零扩展物化值（高 32=0），指针变量装入的是全指针；装载时无需区分。

**表达式层面**：resW==8（long/指针）的路径全部保持 64 位形式不变。

## 3. 窄化点清单（movsxd / 32 位处理），逐一论证

| # | 消费点 | 改造 | 论证 |
|---|---|---|---|
| N1 | genBinary `+ - *`（resW==4） | `add eax,r10d` / `sub r10d,eax; mov eax,r10d` / `imul eax,r10d`，删除尾随 canonInt | 32 位 op 原生回绕+零扩展，产物即物化值 |
| N2 | genBinary `/ %`（resW==4） | 有符号：`mov r11d,eax`(除数) `mov eax,r10d`(被除数) `cdq` `idiv r11d`，商在 eax；取模 `mov eax,edx`。无符号：`mov r11d,eax` `mov eax,r10d` `xor edx,edx` `div r11d`。删除 canonInt+cqo+idiv r11 | `cdq` 把 eax 符号扩展到 edx:eax（32 位除法语义正确）；`idiv r11d` 除数按低 32 位有符号解读，零扩展的高位不影响。每条省 2 条。**不需 movsxd**。INT_MIN/-1 溢出陷阱行为与现状一致（UB） |
| N3 | genBinary `<< >>`（resW==4） | `mov ecx,eax`(count) `mov eax,[rbp-off]`(左) `shl/sar eax,cl`，删除前后 canonInt | 32 位移位回绕+符号位正确（sar 用 bit31） |
| N4 | genBinary `& \| ^`（resW==4） | `and/or/xor eax, r11d`，删除 canonInt | 同上 |

### 3.1 已知遗留（保持现状，不扩大范围）

- `int s = "hello"` 这类指针-in-int：**槽全宽语义保持不变**（N15/N16），指针在
  ptr 消费点（解引用、ptr 参数、varargs %s、ptr 比较）完整流动——现状行为不回归。
- `s + 1`（int 算术作用于指针-in-int）现状即经 canonInt 截断，改造后同样截断——无回归。

## 4. ptrCapable 分析（新，小 pass）

**目的**：识别“可能持有 64 位指针的 int 型变量”，仅在 N5b/N11/N12/N17（`(long)`）四处
**抑制 movsxd**（保持全宽值按原样流动，与现状一致），其余 int 消费点按低 32 位截断语义（与现状 canonInt 一致）。

**规则（保守，任一命中即标记）**：
1. 被赋值为/初始化为指针类型表达式（KPtr/KFunc/KArr 衰减、字符串字面量）的 int 变量；
2. 作为实参传给声明为指针类型的形参的 int 变量；
3. 作为返回值流出声明为指针类型的函数；
4. 赋给指针类型左值；
5. 与指针类型操作数比较；
6. 作为 Index 基址 / `->` 基址 / 解引用 `*` 操作数。

实现：AST 遍历，产出 `map[uid]bool` 或 `varInfo.ptr` 标志；loadVar 读到标记变量时置
`c.resPtr = true`（resW 保持 4）。窄化点检查该标志决定是否 movsxd。文件放新文件 `src/ptrcap.go`。

**风险与对策**：分析漏标 → 指针在 N5b/N11/N12/N17 处被 movsxd 截断（病态代码，语义本就未定义）。
回归套件（gocregress 463 + cstd 60 + c23 49 + examples）为仲裁；若命中，把对应用法定性为规则补充进分析。
